# API для разработчиков

Публичная справка доступна на `/developers`, управление ключами — на `/account/developers`. Примеры приведены для Bash и не выполняются автоматически. Установите `ANON_BASE_URL` в адрес сервиса и `ANON_API_KEY` в выданный секрет. Имена файлов и данные вымышлены.

## Авторизация

Администратор или владелец аккаунта создаёт и отзывает ключи. Секрет показывается один раз и не может быть получен повторно; храните его в защищённом хранилище. На аккаунт допускается до 20 активных ключей. Ключ имеет вид `anon_<accountId>_<случайная часть>`; сервер хранит SHA-256 секрета. Передавайте ключ в каждом запросе в заголовке `Authorization: Bearer $ANON_API_KEY`. Не помещайте его в URL, клиентский код или репозиторий.

Bearer-ключ обязателен даже при наличии сессии и при отключённой обязательной авторизации сайта. Пользователь и аккаунт должны быть активны. Отозванный ключ сразу недействителен; при переводе пользователя в другой аккаунт ключ прежнего аккаунта перестаёт действовать.

## Маскирование

`POST /api/v1/anonymize` принимает multipart: обязательный `file` и необязательный `stages` — JSON-объект с булевыми флагами `regex`, `corporate`, `ner`, `llm`, `review`, `subject`. Для неуказанных этапов действуют настройки сервера.

```bash
curl -X POST "$ANON_BASE_URL/api/v1/anonymize" \
  -H "Authorization: Bearer $ANON_API_KEY" \
  -F "file=@sample.txt" \
  -F 'stages={"regex":true}'
```

Ответ `202`: `{"jobId":"…","done":false}`. Сохраните `jobId` в переменную `JOB_ID` и опрашивайте задачу, например раз в 1–2 секунды:

```bash
curl -G "$ANON_BASE_URL/api/v1/anonymize" \
  -H "Authorization: Bearer $ANON_API_KEY" \
  --data-urlencode "jobId=$JOB_ID"
```

Ответ `200` содержит `{"done":false}`, пока задача выполняется. Завершённый ответ содержит `done: true` и поля `anonymized_text`, `mapping`, `summary`, `spans`, `document_base64`, `document_name`, `document_mime`. Отменённая задача возвращает `{"done":false,"cancelled":true}`.

Задача принадлежит создавшему её пользователю: он может опрашивать или отменять её и другим своим ключом. Другие пользователи того же аккаунта не получают доступ к задаче.

```bash
curl -X DELETE -G "$ANON_BASE_URL/api/v1/anonymize" \
  -H "Authorization: Bearer $ANON_API_KEY" \
  --data-urlencode "jobId=$JOB_ID"
```

Отмена кооперативная: выполняющийся этап может остановиться не сразу. Завершённая задача сохраняет своё терминальное состояние.

## Восстановление

`POST /api/v1/deanonymize` принимает multipart с полями `file` и `mapping` (JSON-строка):

```bash
curl -X POST "$ANON_BASE_URL/api/v1/deanonymize" \
  -H "Authorization: Bearer $ANON_API_KEY" \
  -F "file=@sample.anon.txt" \
  -F 'mapping={"[PERSON_1]":"Пример"}'
```

Вместо multipart можно отправить JSON с `filename`, `file_base64` и объектом `mapping`. Ответ содержит `restored_text`, `leftover` (плейсхолдеры без значений), `document_base64`, `document_name`, `document_mime`. Восстановление детерминированное, без ИИ. Mapping позволяет восстановить исходные данные и требует защищённого хранения.

## Ошибки и квота

- `400` — некорректный запрос или отсутствует обязательное поле.
- `401` — ключ отсутствует или недействителен.
- `402` — квота аккаунта исчерпана.
- `403` — доступ запрещён.
- `404` — задача не найдена или недоступна пользователю. Задачи также могут исчезнуть после истечения срока хранения или перезапуска.
- `5xx` — ошибка обработки или связи с сервисом.

Квота маскирования общая с сайтом. Перед постановкой проверяется, не исчерпана ли она; резервирования страниц нет, а расход учитывается отдельным импортом. Поэтому проверка не является жёстким ограничением параллельных запросов. Восстановление квоту не расходует.

## Проверка реализации

Изолированные проверки: `node --test tests/api-access.test.cjs` — 13 тестов
проверки ключа, ролей, отзыва, принадлежности заданий и квоты. Браузерная
проверка с синтетическим API — 8 сценариев при ширинах 1280 и 390px:
документация, гостевой переход, ограничение участника, выпуск и отзыв ключа.
Также выполнены TypeScript и сборка Turbopack. Для сборки задан изолированный
URL БД; предупреждения Prisma при инициализации PRAGMA ожидаемы при недоступной
базе. Реальные ключи, учётные записи и задания не создавались; локальная БД
и её схема не изменялись. Полную обработку документов следует проверить
в развёрнутом окружении с подключённым Python-бэкендом.
