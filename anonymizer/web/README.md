# Анонимизатор — веб-интерфейс (Next.js)

## Публичные страницы и поиск

Главная `/` проверяет сессию на сервере и отдаёт гостю готовый HTML лендинга.
Рабочий интерфейс вошедшего пользователя находится в `app/Workspace.tsx`;
ответ главной зависит от сессии и не должен кешироваться публичным прокси.
`/welcome` отдаёт тот же лендинг любому посетителю (в т.ч. вошедшему — кнопка
«О сервисе» из меню рабочего места); canonical указывает на `/`, чтобы страница
не конкурировала с главной в индексе.

Для поиска доступны `/pricing`, `/on-premise`, `/developers`, `/formats/docx`,
`/formats/pdf`, `/formats/excel` и `/guides/pseudonymization-and-ai`.
Каталог `/pricing` читает только публичные поля продаваемых планов из той же
БД, что и оплата; пробные и служебные планы в него не входят. Страница `/billing`
остаётся интерфейсом оплаты после входа. Базу не нужно пересоздавать или заполнять
seed ради публикации этих страниц.

`SITE_URL` задаёт канонический публичный адрес. Необязательные
`GOOGLE_SITE_VERIFICATION` и `YANDEX_SITE_VERIFICATION` добавляют метатеги
подтверждения прав; при действующем подтверждении через DNS или HTML-файл
новые теги не нужны. Существующий файл подтверждения Яндекса сохранён.
Пошаговые действия владельца и проверки после публикации:
[docs/seo-launch.md](docs/seo-launch.md).

Проверки: `node --test tests/seo.test.cjs`, `npx tsc --noEmit`, `npm run build`.
Счётчики сторонней аналитики автоматически не подключаются; содержимое документов,
mapping, контакты заявок и данные рабочего интерфейса нельзя передавать в аналитику.

Загружаешь документ (`.docx`, `.doc`, `.xlsx`, `.xls`, `.odt`, `.rtf`, `.xml`, `.pdf`,
`.txt`/`.csv`/`.md`/`.json`) → получаешь **маскированную** версию в том же
формате +
`mapping` (ключ восстановления). ZIP, отдельный документ, отдельный JSON и
превью прямо на странице.

> **Правовая оговорка.** Операция обратима: таблица соответствий (`mapping`)
> сохраняется и позволяет восстановить исходный текст. Поэтому результат
> **не является обезличиванием** в значении п. 9 ст. 3 Федерального закона
> от 27.07.2006 № 152-ФЗ и сохраняет статус персональных данных. В интерфейсе,
> документации и переговорах используются термины «маскирование»,
> «псевдонимизация», «удаление прямых идентификаторов».
> См. `../ЮРИДИЧЕСКИЕ_ДОКУМЕНТЫ/05_ГЛОССАРИЙ_терминологии.md`.

## Размещение

Фронтенд и бэкенд размещаются **на территории Российской Федерации**
(инфраструктура ООО «Интерфоника», г. Иркутск). Размещение в зарубежных
облачных регионах не допускается — см. ч. 5 ст. 18 152-ФЗ (локализация) и
`../ЮРИДИЧЕСКИЕ_ДОКУМЕНТЫ/01_АКТ_о_прекращении_использования_ЕС-контура.md`.

## Архитектура

```
Браузер ──> Next.js (РФ)              ──>  Python backend (server.py)
            /api/anonymize  (прокси)       /anonymize-file
            + Bearer-токен (server-side)   regex + GLiNER + LLM
```

Фронт тонкий: он не запускает GLiNER/PyTorch, вся обработка идёт на
Python-бэкенде (`../server.py`). URL бэкенда задаётся переменной окружения,
токен подставляется на сервере и в браузер не попадает.

| Сценарий | `ANONYMIZER_BACKEND_URL` | Где запущен фронт |
|---|---|---|
| Локальный тест | `http://127.0.0.1:8000` | локально (`npm run dev`) |
| Продуктивный контур | URL бэкенда на площадке в РФ | площадка в РФ |

> При локальной разработке облачный фронт **не увидит твой `127.0.0.1`**.
> Для локальных тестов запускай фронт локально (`npm run dev`), а развёрнутый
> фронт указывай на публичный бэкенд в контуре РФ.

## 1. Локальный тест (LM Studio + GLiNER)

**Шаг 1. LM Studio** — загрузи `gemma4:12b`, включи сервер на
`http://127.0.0.1:1234`.

**Шаг 2. Python-бэкенд** (из каталога `privacy-filter-main`, т.е. на уровень
выше `anonymizer/`):

```bash
python anonymizer/server.py --port 8000 \
  --ner gliner --device cuda \
  --corporate \
  --llm --llm-base-url http://127.0.0.1:1234/v1 \
  --llm-model gemma4:12b --llm-no-think
```

- нет GPU → `--device cpu`;
- проверить без LLM/GLiNER (только regex) → убери `--llm` и поставь `--ner none`;
- здоровье: `curl http://127.0.0.1:8000/health`.

**Шаг 3. Фронт:**

```bash
cd anonymizer/web
cp .env.local.example .env.local   # ANONYMIZER_BACKEND_URL=http://127.0.0.1:8000
npm install
npm run dev                        # http://localhost:3000
```

## 2. Развёртывание продуктивного контура

1. Площадка — **только на территории РФ**. Регион размещения должен быть
   зафиксирован документально (договор с провайдером + подтверждение адреса ЦОД).
2. Environment Variables:
   - `ANONYMIZER_BACKEND_URL` = URL бэкенда в контуре РФ;
   - `ANONYMIZER_BACKEND_KEY` = Bearer-токен бэкенда.
3. Перед выкладкой убедиться, что в конфигурации платформы **не задан зарубежный
   регион исполнения**. Файл `vercel.json` с `regions: ["fra1"]` удалён
   16.08.2026 и не подлежит восстановлению.

Бэкенд поднимается тем же `server.py`, LLM указывает на инференс-эндпоинт,
размещённый в контуре РФ.

## Вкладки

Публичная главная использует название AnonAI. Ссылка «Как это работает» ведёт
на `/guides` с порядком работы и руководствами WORD, PDF, Excel и другими
форматами (`/formats/other`). Кнопки форматов на главной показывают пояснения
при наведении, фокусе и нажатии; блок внедрения расположен ближе к концу страницы.
Текущие темы главной и тарифов сохранены. Неутверждённые варианты элементов
для обеих тем находятся в `docs/brandbook-preview.html`, описание —
в `docs/brandbook.md`; они не подключены к публичному сайту.

На лендинге есть блок внедрения в инфраструктуре заказчика и форма заявки.
Телефон обязателен; компания и email необязательны. Публичный `POST /api/leads`
валидирует поля и согласие на связь, ограничивает размер и частоту запросов,
проверяет Origin и скрытое поле от ботов. Контакты не записываются в БД или логи.
При успешной отправке SMTP-сервер должен подтвердить приём письма; отсутствие
настроек или ошибка SMTP не превращаются в сообщение об успехе.

Для писем заполните в окружении **сервиса Next.js** `LEADS_SMTP_HOST`,
`LEADS_SMTP_PORT` (по умолчанию 465), `LEADS_SMTP_USER`, `LEADS_SMTP_PASSWORD`.
При необходимости задайте `LEADS_SMTP_FROM` и `LEADS_TO_EMAIL`; получатель по
умолчанию - почта владельца из `lib/legal.ts`. Все параметры перечислены в
`.env.local.example`. Используйте почтовый сервер в РФ и пароль приложения.
SMTP-соединение всегда шифруется: TLS на 465 или обязательный STARTTLS на других
портах; проверка сертификата не отключается. Перезапустите веб-сервис после
изменения окружения. Подтверждение SMTP означает приём сервером для доставки,
поэтому при проверке настройки проверьте также папку «Спам» получателя.

Ограничитель заявок хранится в памяти одного процесса: 5 запросов за 15 минут
на источник и 30 за час суммарно. nginx должен перезаписывать `X-Real-IP`
(как в `deploy/nginx-anonymizer.conf`), а порт Next.js не должен быть доступен
в обход nginx. Для нескольких процессов нужен общий ограничитель. Проверки
`node --import tsx --test tests/leads.test.ts` не отправляют настоящие письма.

Главная страница `/` после проверки сессии гостю отдаёт готовый HTML лендинга,
а вошедшим пользователям сразу показывает рабочий экран. Разделы `/billing`,
`/account/subscription`, `/account/payments` и `/?tab=account` направляют гостей
на вход, сохраняя исходный адрес с параметрами и фрагментом в `next`.
После входа открывается этот адрес; внешние адреса возврата не допускаются.
`/welcome` также доступна по ссылке «О сервисе» из меню. Демонстрация использует
вымышленные данные, поддерживает паузу и системную настройку уменьшения движения.

- **Маскирование** — загрузка документа, выбор этапов, превью + скачивание
  (документ / `mapping.json` / ZIP).
- **Восстановление (деанонимизация)** — восстановление по `mapping` (без ИИ).
  По умолчанию берёт **последний** маскированный документ и его `mapping`
  (галочка «Использовать последний документ»). Сними галочку — можно загрузить
  свой маскированный файл (в исходном формате) и свой `mapping.json`.

## Администрирование владельцем сервиса

В меню аккаунта пользователю с ролью `root` доступен раздел
«Администрирование» (`/admin`). Он показывает аккаунты всех клиентов,
их пользователей и текущие квоты; поиск работает по email пользователя и
названию аккаунта. Список разбит по 25 аккаунтов, в каждом показаны первые
100 пользователей и их общее число.

Владелец может установить индивидуальный базовый лимит страниц аккаунта
с точностью до 0,1 страницы (включая ноль) или вернуть лимит тарифа.
Это общий лимит всех участников аккаунта за период, а не новый остаток:
расход не сбрасывается, имеющиеся добавочные страницы продолжают учитываться.
Исключение хранится в существующем `Account.pageLimitOverrideTenths` и действует
в следующих периодах и при смене тарифа, пока владелец не вернёт лимит тарифа.
Изменение лимита не продлевает срок подписки и не включает отключённый аккаунт.

В блоке «Срок доступа» владелец может бесплатно выдать доступ по текущему тарифу
до любой даты и времени в UTC, сократить срок (в том числе указать прошлую дату
для прекращения доступа) или снять ограничение срока кнопкой «Без срока».
Указанный момент окончания не включается: начиная с него обработка недоступна.
Быстрые варианты «1 месяц», «2 месяца», «1 год» заполняют поле от текущего момента
календарными месяцами с учётом последнего дня месяца. Они требуют отдельного
сохранения и заменяют дату окончания, а не добавляют срок к прежнему окончанию.

Ручное изменение срока не создаёт платёж и не меняет тариф, лимит страниц,
накопленный расход, дополнительные страницы или якорь расчётных периодов.
После продления истёкшего срока квота продолжает рассчитываться по прежнему
месячному графику; у аккаунтов без якоря сохраняются календарные месяцы по UTC.
«Без срока» снимает только дату окончания, а не ограничение страниц.
Миграция БД не нужна: используются существующие поля аккаунта.

`GET/PATCH /api/admin/accounts` требуют сессию активного владельца, текущую
роль `root` и активность аккаунта из БД; роль `admin` доступа не даёт.
PATCH проверяет Origin (за прокси укажите публичный `AUTH_URL`). Ответы
не кешируются; пароли, ключи и содержимое документов не передаются.
Проверки без рабочей БД: `node --test tests/root-admin.test.cjs`.

## Подписка и оплата

В нижней части бокового меню расположен блок аккаунта с текущим тарифом,
переходами к подписке и платежам, настройками и выходом. `/billing` — витрина
тарифов с выбором месяца или года и способа оплаты: личной картой или для
организации. Третий переключатель «API» показывает отдельный прайс 2 ₽ за
страницу и ссылки на управление ключами и документацию; подписочные карточки
и выбор месяца/года в нём скрыты. В годовых подписках зачёркнутая сумма -
стоимость 12 отдельных месяцев, рядом показаны фактическая цена за год и
экономия. Оплата картой открывает существующий checkout Т-Банка; выбор
организации ведёт на `/account/payments?plan=...&months=...#transfer`.

На `/account/subscription` показаны текущий тариф, срок и квота;
`/account/payments` содержит историю платежей и реквизиты для банковского
перевода. Анкета для организации не требуется. Банковский перевод не создаёт
счёт и не активирует тариф автоматически; сверка платежей не реализована.

`GET /api/billing/bank-details` только читает данные: требует авторизованную
сессию, активные пользователя и аккаунт в базе, совпадение аккаунта с сессией
и роль `admin` или `root` из базы. Цена выбранного тарифа и срока берётся из
базы, назначение платежа формируется для аккаунта сессии. Маршрут не обращается
в банк, не записывает данные и не активирует тариф.

Для реквизитов обязательны серверные переменные `BANK_TRANSFER_BANK_NAME`,
`BANK_TRANSFER_BIC`, `BANK_TRANSFER_ACCOUNT` и `BANK_TRANSFER_CORR_ACCOUNT`;
наименование получателя, ИНН, ОГРНИП и адрес берутся из `LICENSOR` в `lib/legal`.
Необязательные `BANK_TRANSFER_BANK_INN` (10 цифр) и `BANK_TRANSFER_BANK_ADDRESS`
(до 500 символов без управляющих символов) добавляют ИНН и адрес банка. Если
обязательный набор отсутствует или любое заданное поле не проходит проверку,
интерфейс сообщает, что реквизиты не настроены, и частичные значения не выдаются.

## API бэкенда

`POST /anonymize-file` (JSON):

```json
{ "filename": "doc.docx", "file_base64": "...", "regex": true, "ner": true, "llm": true }
```

Ответ: `anonymized_text`, `mapping`, `summary`, `spans`, `document_base64`,
`document_name`, `document_mime`. Флаги этапов опциональны (по умолчанию — как
запущен сервер).

`POST /deanonymize-file` (JSON):

```json
{ "filename": "doc.anon.docx", "file_base64": "...", "mapping": { "[PERSON_1]": "Иванов И.И." } }
```

Ответ: `restored_text`, `leftover` (плейсхолдеры без значения), `document_base64`,
`document_name`, `document_mime`. Восстановление детерминированное, без ИИ.

## API для разработчиков

Публичная справка и примеры запросов доступны на `/developers` и в
[docs/developer-api.md](docs/developer-api.md). Администраторы и владельцы
аккаунта управляют ключами на `/account/developers`. API использует отдельный
Bearer-ключ и общую с сайтом квоту маскирования.

При выпуске и отзыве ключей проверяется Origin запроса. За обратным прокси
задайте серверный `AUTH_URL` равным публичному адресу, по которому открывается
сайт (например, `https://anon.example.ru`): внутренний `localhost` в адресе
запроса Next.js не должен использоваться вместо публичного домена. Без
`AUTH_URL` применяется Origin адреса запроса, что подходит для прямого
локального запуска. Разрешённые роли проверяются по БД: `root` и `admin`;
`member` не может управлять ключами. Отказ из-за источника запроса показывается
отдельно от отказа в правах.
