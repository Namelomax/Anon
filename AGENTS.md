# Инструкции по работе с проектом

## Назначение

Anon — существующий сервис обратимого маскирования (псевдонимизации)
персональных данных в русскоязычных текстах и документах. Найденные значения
заменяются плейсхолдерами вида `[PERSON_1]`; таблица `mapping` позволяет
детерминированно восстановить исходные значения без ИИ.

Общаться с пользователем и писать пояснения по умолчанию на русском языке.
Имена в коде и стиль изменений согласовывать с окружающим кодом.

## Оркестрация агентов

Пользователь разрешает делегирование без повторного запроса. `gpt-6.1-sol`
принимает решения и проверяет результат; обычный код, тесты, документацию и
простой текст по возможности поручать `gpt-6.1-terra` для экономии лимитов.
Sol задаёт короткое ТЗ, файлы и границы работы, а также критерии результата;
Terra выполняет задачу. При явном выборе модели в `spawn_agent` использовать
`fork_turns="none"` и передавать только необходимый контекст.

Число исполнителей выбирать по количеству независимых задач: при большом объёме
запускать несколько сразу, до десяти задач исполнителей одновременно, если
среда предоставляет достаточно слотов. Настроенный лимит исполнителей — 10,
Sol работает отдельно. Фактическое число одновременно работающих агентов
ограничивается доступными слотами текущей сессии.
Для небольшой задачи достаточно одного исполнителя. Не допускать вложенного
делегирования и конкурирующих правок одних файлов. Если независимых задач больше
доступных слотов, запускать следующие по мере завершения предыдущих.
Архитектуру, неоднозначные ошибки, безопасность, биллинг и финальную проверку
оставлять Sol. Не вызывать агента ради односложного ответа или крошечной правки,
если накладные расходы выше пользы. Если Terra недоступна, сообщить об этом,
не заменяя её молча. Не обещать процент экономии или гарантировать тариф.
Эти правила не переключают модель активного чата.

## Карта репозитория

- `anonymizer/` — Python-пакет и сервис обработки документов.
- `anonymizer/__init__.py` — публичный Python API.
- `anonymizer/engine.py` — сборка и выполнение конвейера детекции.
- `anonymizer/detectors.py`, `spans.py` — детекторы, интервалы и пересечения.
- `anonymizer/mapping.py`, `deanonymize.py` — плейсхолдеры и восстановление.
- `anonymizer/ner.py`, `gliner_ner.py`, `gliner_remote.py` — NER-бэкенды.
- `anonymizer/llm.py`, `review.py` — LLM-детекция и проверка результатов.
- `anonymizer/documents.py` — обработка форматов документов.
- `anonymizer/server.py` — HTTP API, авторизация, задания обработки.
- `anonymizer/worker.py` — обработчик заданий.
- `anonymizer/app.py` — альтернативный интерфейс Streamlit.
- `anonymizer/anonymize_document.py` — CLI для обработки документов.
- `anonymizer/usage_log.py`, `usage_report.py` — учёт использования.
- `anonymizer/tests/` — Python-тесты; `test_samples/` — примеры для проверок.
- `anonymizer/web/` — Next.js 15, React 19, TypeScript, NextAuth, Prisma.
- `anonymizer/browser-extension/` — прототип Chrome MV3: выделение текста, боковая панель, Bearer API v1 и локальное восстановление; mapping, ключ и подписи из первых восьми слов хранятся только в `chrome.storage.session`. Установка и ограничения — в README расширения; проверки: `npm test` из его каталога.
- `anonymizer/web/app/` — страницы и API-маршруты App Router.
- `anonymizer/web/app/api/leads/`, `lib/leads.ts` — заявки на внедрение через SMTP; форма на лендинге — `app/_components/OnPremiseLead.tsx`. Настройки `LEADS_SMTP_*` и `LEADS_TO_EMAIL` только серверные; контакты заявок в логи не писать.
- `anonymizer/web/app/developers/`, `anonymizer/web/docs/developer-api.md` — публичная справка API для разработчиков и примеры запросов.
- `anonymizer/web/app/account/developers/` — выпуск и отзыв API-ключей через `app/api/account/api-keys/`; `app/api/v1/` — программный доступ к обработке, `lib/api-keys.ts` — проверка ключей. Новая схема БД для этого не требуется.
- `anonymizer/web/app/billing/` — витрина тарифов и выбор оплаты; `app/account/subscription/` — текущий тариф и квота, `app/account/payments/` — история платежей и банковский перевод. Меню аккаунта внизу боковой панели — `app/_components/AccountMenu.tsx`.
- `anonymizer/web/app/api/billing/bank-details/` — доступные администраторам реквизиты и расчёт банковского перевода только для чтения; настройки описаны в веб-README.
- `anonymizer/web/lib/` — авторизация, квоты, биллинг, платежи и общая логика.
- `anonymizer/web/prisma/` — схема SQLite, миграции и seed.
- `deploy/` — конфигурации nginx/systemd, зависимости API и инструкции выкладки.
- `anonymizer/ЮРИДИЧЕСКИЕ_ДОКУМЕНТЫ/` — требования, решения и документы проекта.

## С чего начинать задачу

1. Проверить `git status --short`, сохранить существующие изменения пользователя.
2. Прочитать файлы затрагиваемого компонента и ближайшие тесты.
3. Для общего устройства читать `anonymizer/README.md`; для веб-интерфейса —
   `anonymizer/web/README.md`; для инфраструктуры — `deploy/DEPLOY.md`.
4. Сверять команды и поведение с кодом: часть README описывает ранние этапы
   разработки и может отставать от реализации.
5. После существенного изменения структуры обновлять этот файл.

## Локальная работа

Команды Python выполнять из корня репозитория; команды npm — из
`anonymizer/web/`. В Windows используется PowerShell. Текст читать и сохранять
в UTF-8 (в PowerShell при необходимости указывать `-Encoding UTF8`).

Зависимости выбирать под задачу:

- `requirements.txt` — окружение с локальным GLiNER и обработкой документов.
- `deploy/requirements-api.txt` — API без локальных моделей и PyTorch,
  рассчитанное на удалённый инференс.
- Не переустанавливать PyTorch/CUDA без необходимости: конфигурация зависит
  от оборудования. Не загружать модели для изменений, которым они не нужны.

Минимальный запуск API без NER, LLM и review:

```powershell
python anonymizer/server.py --ner none --no-llm --no-review --host 127.0.0.1 --port 8000
```

Полный запуск по умолчанию включает тяжёлые этапы и требует настроенного
окружения. Авторизацию и переменные окружения смотреть в `server.py` и
`deploy/anonymizer.env.example`; реальные секреты в инструкции не копировать.

Веб-интерфейс:

```powershell
Set-Location anonymizer/web
npm ci
# При первом запуске создать .env.local по .env.local.example и заполнить локальные настройки.
npm run dev
```

Настройку базы и авторизации сверять с веб-README и схемой Prisma.
Не запускать seed, миграции или платёжные скрипты против рабочей базы
для проверки изменений интерфейса.

## Проверки

Выбирать существующие проверки по затронутому поведению. Например:

```powershell
python -m pytest anonymizer/tests/test_engine.py -q
python -m pytest anonymizer/tests/test_llm.py -q
# Более широкий прогон при изменениях нескольких компонентов:
python -m pytest anonymizer/tests -q
```

Часть проверок требует дополнительных зависимостей, моделей или сервисов.
В отчёте отличать успешную проверку от пропуска или отсутствующего окружения.

Для изменений TypeScript и веб-сборки из `anonymizer/web/`:

```powershell
npx tsc --noEmit
npm run build
```

В `package.json` есть `npm run lint` с командой `next lint`; совместимость
этой команды с установленной версией Next.js нужно проверить перед использованием.
Для изменений только документации достаточно проверить содержимое и `git diff --check`.

## Инварианты проекта

- Сохранять обратимость, согласованность `mapping` и точность границ замен.
  Изменения детекции проверять на пропусках, ложных срабатываниях и восстановлении.
- LLM предлагает находки; код проверяет подстроки, вычисляет позиции и выполняет
  замену. Не доверять выдуманным моделью значениям или смещениям.
- При изменениях review учитывать детерминированную защиту от снятия масок
  с PERSON; смотреть соответствующие тесты `test_person_unmask_gate.py`
  и `test_review_person_gate.py`.
- Не добавлять исходные персональные данные, mapping, токены, пароли и содержимое
  документов в логи, коммиты или примеры. Для тестов использовать синтетические данные.
- Секреты Python-бэкенда остаются на сервере Next.js и не передаются в браузер.
  Сохранять проверки авторизации и принадлежности заданий пользователю.
- Публичный API v1 всегда требует Bearer-ключ, включая режим разработки.
  Неверный явный ключ не заменять сессией. Хранить только SHA-256 ключа,
  показывать секрет лишь при выпуске, проверять отзыв и активность пользователя
  и аккаунта. При смене аккаунта старый ключ недействителен; деньги и квоты
  нельзя брать из клиентских идентификаторов. Управление ключами требует сессии
  администратора и проверки текущей роли в БД.
- Учитывать зафиксированные в документации проекта требования размещения в РФ.
  Продуктовая терминология: «маскирование» и «псевдонимизация»;
  не обещать необратимое обезличивание при сохранении mapping.
- В биллинге деньги хранятся целыми копейками, страницы — целыми десятыми долями.
  Перед изменениями квот читать комментарии к `prisma/schema.prisma`.
- Корневой `.gitignore` использует список разрешённых путей. Новые корневые
  файлы проверять через `git check-ignore`, при необходимости добавлять исключение.
- Не редактировать сгенерированные файлы, зависимости и локальные базы вместо исходников.
  Не выполнять выкладку или реальные платежи без соответствующей задачи пользователя.
